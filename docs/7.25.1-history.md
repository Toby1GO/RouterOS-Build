## 修改

- loader：新增独立 RX 入口段，启动时修改自身导入的 memcmp 函数指针，随后恢复通用寄存器及标志并返回原 ELF 入口。保留原始各节内容，特别是先前识别的三个握手相关区域；只修改 ELF 入口及一个程序段头，并追加数据。
- memcmp 替代函数返回零，作用于 loader 自身经该动态入口执行的比较，不仅限于某次授权比较。此行为范围较宽，不能当作保留原验证语义的修复，也不能声称关闭了所有进程的校验。
- 将实际路径 nova/bin/keyman、nova/bin/mode 替换为使用自有许可证公钥的对应文件。此前只存在于下划线副本中的修改现在应用于实际启动路径。
- 原 sysinit 不变，没有暂停、trace、keygen 或 rc.local 注入。未生成 IMG。

## 验证

- SquashFS 重建后读回，与第六版对比，仅上述三个文件内容发生变化。文件名、权限、属主、时间、链接及设备节点元数据保留。
- 从交付 ISO 读回 12 个 NPK 并验签。
- ISO 原文件位置及除主系统包外的所有文件内容不变。
- BIOS、UEFI 和安装后使用的包内内核一致，CRC32 有效。
- ELF 新增段映射以及寄存器、标志、栈和回到原入口的行为通过隔离 CPU 模拟。替代比较函数对不相等输入返回零也已确认。
- 确认实际 keyman/mode 等于原始程序应用自有许可证公钥替换后的结果。
- 未启动虚拟机，未证明服务握手、实际登录或许可证导入成功。第六版基线和所有旧输出均保留。

## 用户测试顺序

1. 新建空白虚拟硬盘，以原 BIOS/SCSI 配置安装第七版，安装后移除 ISO。
2. 先确认进入登录界面且不再自动重启。
3. `/system license print` 获取该次安装真实的 Software ID，不沿用旧虚拟机示例 ID。
4. 在项目目录执行 `python license.py licgenros 实际SoftwareID --output device-r7.key`。默认使用原有 `.private/signing.env`，不要重新生成密钥对。输出文件名必须尚不存在。
5. 导入完整许可证文本，检查授权状态；如可用，再重启确认状态持久化。

如果仍失败，请区分“启动失败”或“能登录但许可证无效”。启动失败时保留虚拟磁盘读取 `rw/logs/backtrace.log*`；许可证无效时保留实际 Software ID、所用许可证文件以及完整错误文字，不需要提供或显示私钥。
